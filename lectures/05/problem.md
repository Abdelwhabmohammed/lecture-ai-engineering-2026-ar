# Lecture 05 — التمرين والواجب: البحث في مواد المحاضرات للإجابة

> **حالة الإصدار:** التعليمات وقالب الإجابة جاهزان. إصدار مجموعة المواد العربية وفهرس البحث وتفعيل شيفرة Lecture 05 في `main` ما زالت معلّقة. اتبع أوامر التشغيل أدناه بعد إصدار البيانات والشيفرة لاحقًا.

## أهداف هذه المحاضرة

- تشغيل الإجابة بتمرير النص الكامل وباستخدام البحث، ومقارنة الإجابات والأدلة والوقت وعدد التوكنات
- شرح البيانات التي تمثّل كل صفحة بمقطع واحد، والفرق بين طرق الاسترجاع بالبحث المتجهي وTree وGraph
- تحسين طريقة الاسترجاع لتناسب استخدامك، والتحقق من أثر التغيير باستخدام السؤال نفسه

سنستخدم صيغة «نموذج + حلقة + أدوات» من Lecture 03، ونغيّر طريقة استرجاع مواد المحاضرات. بالاستناد إلى التقييم في Lecture 04، ستتحقق بنفسك من صحة الإجابة والأدلة في الصفحات المستشهد بها.

## التحضير

### 1. اجلب تحديث Lecture 05 وأنشئ فرع lec05

بعد نشر تحديث بيانات Lecture 05 وشيفرة تشغيله في `main`، وليس تحديث هذه التعليمات وحده، اضغط **Sync fork → Update branch** في نسختك المتفرعة، ثم نفّذ الأوامر التالية في طرفية Codespaces:

```bash
git switch main
git pull --no-rebase
git switch -c lec05
uv sync --frozen
```

- إذا كان الفرع `lec05` موجودًا بالفعل، فانتقل إليه باستخدام `git switch lec05`
- إذا منعتك تغييرات متبقية من المحاضرة السابقة من التبديل، فاحفظها في commit على ذلك الفرع ثم أعد المحاولة
- إذا ظهر تعارض أثناء التحديث، فاستشر المدرّس دون حذف تغييراتك

استخدم مفتاح API في متغير البيئة `GEMINI_API_KEY` نفسه المستخدم في Lecture 01. إذا أضفت السر في Codespaces بعد تشغيله، فأعد تشغيل Codespaces. راجع [README](../../README.md) لمعرفة طريقة الإعداد.

### 2. تحقق من قاعدة بيانات البحث بعد إصدارها

قاعدة البيانات العربية `data/rag_data/index.sqlite3` ليست مرفقة بهذا الإصدار بعد. بعد إصدار البيانات والشيفرة وجلب تحديثهما، سيستخدم البحث المتجهي وGraph قاعدة البيانات المرفقة كما هي؛ عندها انتقل إلى التمرين. يُستخدم `GEMINI_API_KEY` لتضمين الأسئلة وتوليد الإجابات. لا يحتاج Tree ولا تمرير النص الكامل إلى قاعدة بيانات البحث، لكنهما يحتاجان إلى ملفات المواد وشيفرة التشغيل التي لم تُفعّل في `main` بعد.

## التمرين

### الخطوة 1: مرّر المواد دفعة واحدة لتوليد إجابة

أولًا، ضع سؤال المقارنة في متغير ضمن الطرفية نفسها. استخدم هذا السؤال كما هو مع كل طريقة أدناه.

```bash
AIE_QUESTION='وفقًا لشرح Lecture 02، ما الذي يثبّته LoRA وما الذي يدرّبه؟ وما الذي يضيفه QLoRA؟'
uv run python -m app.agent --full-context --trace "$AIE_QUESTION"
```

سجّل الإجابة والصفحات المستشهد بها، وقيم `[time]` و`[usage]` و`[cost]` الظاهرة في النهاية، في [answer.md](answer.md).

قد ينجح تمرير النص الكامل أيضًا في تقديم إجابة صحيحة. انظر إلى النتيجة الفعلية دون افتراض أنه سيفشل. سجّل بصورة منفصلة أخطاء تجاوز حد الإدخال، والحالات التي يُقبل فيها الإدخال لكن النموذج لا يستخدم الأدلة اللازمة.

### الخطوة 2: افحص نتائج البحث وحدها

```bash
uv run python -m app.retrieval "الفرق بين LoRA وQLoRA"
```

يسترجع هذا الأمر حتى 5 صفحات قريبة من السؤال دون استخدام الوكيل. يعرض اسم المحاضرة والفصل وعنوان الصفحة ورقم صفحة PDF والنص.

- هل تتضمن النتائج صفحات تدعم الإجابة، مثل Lecture 02 · PDF p.52؟
- هل تستطيع التمييز بين صفحة تذكر مصطلحات متشابهة فحسب وصفحة تقدّم دليلًا للإجابة؟

افتح JSON التعليمي في المحرر وابحث، مثلًا، عن `lec02-main-p052` للتحقق من نص الصفحة المعنية.

### الخطوة 3: استخدم نتائج البحث لتوليد إجابة

```bash
uv run python -m app.agent --trace "$AIE_QUESTION"
```

عند التشغيل العادي، يجيب وكيل يملك الأداة `search_materials(query)`. يختار النموذج كلمات البحث، ويجيب باستخدام النصوص المُعادة.

- افحص كلمات البحث وعدد استدعاءات الأدوات في `[tool call]`
- تحقق من أن مراجع «Lecture N · PDF p.N» المرفقة بالإجابة تدعم الشرح
- ميّز بين عدم استرجاع الدليل اللازم وعدم استخدام الدليل المسترجع استخدامًا صحيحًا

يمكن أن تكفي p.52 وحدها لتوفير جميع الأدلة لبعض الأسئلة. لا تجعل زيادة عدد الصفحات المستشهد بها هدفًا بحد ذاته.

### الخطوة 4: أجب عن السؤال نفسه باستخدام Tree وGraph

يتتبّع Tree فهرس المحتويات لاختيار الصفحات.

```bash
uv run python -m app.agent --tree --trace "$AIE_QUESTION"
```

يستخدم `browse_tree(node_id)` وحدها. يبدأ باسترجاع قائمة المحاضرات، ثم يستخدم المعرّفات المُعادة للانتقال إلى المحاضرات والفصول والصفحات. تتضمن الصفحات في `children` الجملة الأولى فقط، وعند تحديد معرّف صفحة يوضع نصها الكامل في `node.content`. إذا لم تتضمن الصفحة علامة نهاية جملة، فالنص المرشح هو السطر الأول. افحص في trace مسار الفهرس المختار والصفحات التي استُرجع نصها الكامل.

يجد Graph نقاط بداية بالبحث المتجهي، ثم يوسّع المرشحات حولها.

```bash
uv run python -m app.agent --graph --trace "$AIE_QUESTION"
```

يستخدم `search_graph(query)`. يبدأ بأفضل 3 صفحات في نتائج البحث، ويتتبّع علاقات الصفحات السابقة واللاحقة والمصطلحات المشتركة حتى 2 hop، ثم يعيد نصوص ما يصل إلى 10 صفحات بما فيها صفحات البداية. الانتقال من صفحة إلى الصفحة المجاورة يساوي 1 hop، والانتقال من صفحة عبر مصطلح إلى صفحة أخرى يساوي 2 hop. تذكّر أن اشتراك الصفحات في المصطلحات لا يعني بالضرورة أنها تتضمن الإجابة.

سجّل كيف تتغير الإجابة والأدلة المستشهد بها والوقت وعدد توكنات الإدخال بين Tree وGraph.

### الخطوة 5: قارن النتائج وسجّلها

لخّص نتائج كل طريقة في جدول `answer.md`.

| المؤشر | المعنى |
|---|---|
| `[time]` | عدد الثواني حتى اكتمال الإجابة، بما في ذلك البحث والتضمين |
| `[usage]` | مجموع توكنات الإدخال والإخراج وعدد استجابات النموذج لسؤال واحد |
| `[cost]` | التكلفة التقديرية لـ API التوليد. لا تشمل تضمين الاستعلام ولا بناء الفهرس |

إذا كانت التكلفة «يتعذر التقدير»، فسجّل ذلك كما هو ولا تعاملها على أنها 0.

إذا سمح الوقت، فغيّر السؤال وكرّر المقارنة نفسها. عند جمع نتائج عدة أسئلة، احتفظ بنتائج منفصلة لكل سؤال.

| النوع | مثال للسؤال | الدليل المطلوب التحقق منه |
|---|---|---|
| عدة صفحات | في أمثلة Lecture 03، ما الفرق بين اختزال السياق (compaction) والذاكرة عبر الجلسات؟ هل تدخل جميع الملاحظات اليومية في الذاكرة طويلة المدى؟ | Lecture 03 · PDF p.13 و39 و40 |
| غير موجود في المواد | ما متوسط زمن الاستجابة المقاس ونسبة الإجابات الصحيحة لنظام RAG الذي أنشأناه هذه المرة؟ | لا تتضمن مواد المحاضرات سجلات قياس فعلية لهذا النظام |

### خطوات المستوى الأساسي

غيّر موضعًا واحدًا فقط في كل مرة من الخيارات التالية:

- `INSTRUCTIONS` في `app/agent.py`. عند استخدام Tree أو Graph، عدّل `TREE_INSTRUCTIONS` أو `GRAPH_INSTRUCTIONS` على الترتيب
- سلسلة توثيق الأداة (docstring) في `app/tools.py`
- `RAG_TOP_K` في `app/config.py` (عدد النتائج المُعادة في البحث المتجهي العادي)

استخدم السؤال والنموذج والمواد نفسها، وراقب تغير استدعاءات الأدوات ووسيطاتها وعددها، والإجابة والأدلة المستشهد بها. سجّل أيضًا الوقت وعدد التوكنات والتكلفة التقديرية لـ API التوليد. لا تتطلب هذه التغييرات وحدها إعادة بناء الفهرس.

### خطوات المستوى التطبيقي

يمكنك مثلًا تحسين `app/retrieval.py` ليعيد نص صفحة واحدة قبل كل صفحة مسترجعة وأخرى بعدها.

1. استخدم معلومات الصفحات من `load_pages()` للعثور على الصفحات السابقة واللاحقة ضمن `document_id` نفسه لنتيجة البحث
2. تجنّب إعادة الصفحة نفسها أكثر من مرة، وأعِد النص مع معلومات الاستشهاد
3. شغّل السؤال نفسه المستخدم قبل التغيير، وافحص مثالًا أضاف أدلة لازمة وآخر زاد المعلومات غير الضرورية
4. سجّل ما نفّذته ونتائج المقارنة والإخفاقات المتبقية

يمكنك اختيار تحسين آخر لعملية الاسترجاع يناسب استخدامك. إذا غيّرت نطاق الاسترجاع وحده دون تغيير النصوص أو إعدادات التضمين، فلا حاجة إلى إعادة بناء الفهرس.

إذا غيّرت نصوص المواد أو إعدادات التضمين، فاتبع [خطوات README](../../README.md#lecture05-retrieval) لتحديد قاعدة بيانات تجريبية عبر `AIE_RAG_DB` قبل بناء الفهرس.

### خطوات المستوى المتقدم

1. حدّد السؤال الذي تريد تمكين النظام من حله. افحص مسبقًا الصفحات التي تدعم الإجابة، مثل شرح يمتد عبر فصول أو مقارنة مصطلحات مترابطة
2. صمّم طريقة الاسترجاع. من الأمثلة: كيفية عرض فهرس Tree ونصوص المرشحات، وأنواع علاقات Graph وعدد hops وطريقة اختيار المرشحات، والجمع بين عدة طرق استرجاع
3. اشرح بنية البيانات وطريقة حفظها والبحث فيها، مع أسباب اختيارك
4. قارن مع RAG الأساسي باستخدام السؤال والنموذج والمواد المستهدفة نفسها. سجّل الإجابة والأدلة المستشهد بها والوقت وعدد التوكنات والتكلفة التقديرية لـ API التوليد
5. قدّم أمثلة تحسنت وأخرى أخفقت، وناقش ما إذا كنت ستعتمد الطريقة لاستخدامك

يمكنك استخدام أدوات الذكاء الاصطناعي. اكتب ما شغّلته وتحققت منه بنفسك. اتبع إعلانات المقرر لمعرفة موعد التسليم.

## عند مواجهة مشكلة

| العَرَض | ما ينبغي التحقق منه |
|---|---|
| لا يُعثر على `GEMINI_API_KEY` | هل سجّلت السر في Codespaces؟ وإذا أضفته بعد التشغيل، فهل أعدت تشغيل Codespaces؟ |
| «قاعدة بيانات البحث غير موجودة.» | غياب قاعدة البيانات متوقّع في إصدار التعليمات الحالي. بعد نشر تحديث البيانات والشيفرة، اجلبه وتحقق من وجود `data/rag_data/index.sqlite3`. إذا ضبطت `AIE_RAG_DB`، فتحقق من المسار المحدد |
| بلوغ حد معدل طلبات API | انتظر وفقًا للرسالة المعروضة ثم أعد المحاولة |
| رسالة تفيد بأن السؤال فارغ | إذا فتحت طرفية أخرى، فاضبط `AIE_QUESTION` مجددًا |
| نتائج البحث لا تجيب عن السؤال | جرّب البحث وحده باستخدام `app.retrieval`، وافحص كلمات البحث والمواد المستهدفة وعدد النتائج المُعادة |
| خطأ تجاوز حد الإدخال عند تمرير النص الكامل | سجّل الخطأ وظروف التشغيل، وجرّب الطرق الأخرى. وضّح في الخانات المعنية ما لم تشغّله |

قد تتغير النتائج حتى مع السؤال نفسه. لا تحكم على جودة طريقة كاملة من نجاح أو إخفاق واحد؛ افحص الأدلة التي استُرجعت واستُخدمت.
