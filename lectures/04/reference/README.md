# مواد مرجعية لـ Lecture 04

- `labels_instructor.jsonl`: تصنيفات المدرّس. يشرح `note` حكم كل حالة والإخفاقات التي أُدرجت عمدًا.
  هذه التصنيفات ليست بالضرورة الإجابة الصحيحة؛ غرضها إظهار أن البشر قد يختلفون أيضًا.

للمقارنة مع تصنيفاتك (`lectures/04/labels.jsonl`)، استخدم شاشة «المقارنة» في `tools/annotate.py` أو الأمر التالي:

```bash
uv run python -m app.judge --compare lectures/04/reference/labels_instructor.jsonl
```

## ما أظهره التقييم الفعلي باستخدام gemini-3.5-flash-lite

هذه ملاحظات التشغيل الياباني الأصلي، وليست قياسات أُعيدت بالعربية. نتجت عن تشغيل `app.judge` مع تصنيفات المدرّس باعتبارها «تصنيفاتي»، وأدت إلى التعديلات التالية في `rubric.md` ومجموعة التقييم.

| الملاحظة | التعديل |
|---|---|
| #02، الاستناد إلى المرجع: أعاد fail بسبب عبارة «اذكر Lecture 03 في النهاية» في السلوك المتوقع بالمرجع (مع أن الشيفرة تتحقق من ذكر المحاضرة) | حُذف شرط ذكر Lecture NN في النهاية من السلوك المتوقع، وأُضيف إلى rubric.md أن هذه العلامة لا تدخل في حكم النموذج هنا |
| #06 و#08، الوضوح: نقل أسباب الإخفاق في التلميح أو النطاق إلى الوضوح، فأعطاه fail أيضًا | أُضيف إلى معيار الوضوح في rubric.md: «قيّم سهولة القراءة فقط؛ يُقيَّم المحتوى والدور في المعايير الأخرى»، وإلى طريقة التقييم: «قيّم كل معيار مستقلًا» |
| #04، الوضوح: أعطى pass لإجابة طويلة تكرر الشرح نفسه | وُضّح أن تكرار المحتوى أو إعادة صياغته، مثل إعادة تلخيصه بعبارة «أي إن»، يستحق fail |
| #05، الاستناد إلى المرجع: أعاد pass بدلًا من unsure، وحسم بنفسه مسألة لم تحددها المعايير | أُضيف قسم «مسائل لم تُحسم بعد» في نهاية rubric.md، مع توجيه صريح لإعطاء unsure لما ينطبق عليه. في الخطوة 3، تُحسم المسألة وتُضاف سياستها إلى المعايير |

يميل نموذج التقييم إلى اختيار pass أو fail حتى لمسائل لم تحددها المعايير. قبل المحاضرة، أعد التشغيل باستخدام rubric.md المعدّل وافحص هل تحصل الحالة #05 على unsure.
