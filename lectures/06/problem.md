# تمرين المحاضرة 06 وواجبها — استخدام أدوات خوادم MCP من الوكيل

## أهداف هذه المحاضرة

- استخدم خادم MCP الذي أنشأته من وكيل، مع أداة المسرد من المحاضرة 03.
- اعرض أسماء الأدوات وأوصافها والوسيطات التي يتلقاها النموذج واقرأها.
- استخدم خوادم MCP من مزوّدين آخرين بإضافتها إلى ملف الإعداد.

نفّذ التمرين في GitHub Codespaces من نسختك المتفرعة. استخدم مفتاح Gemini API الذي سجّلته في المحاضرة 01.

## ثلاث طرق لاستخدام خادم MCP

جرّب الحالات الثلاث بالترتيب.

| | تشغيل خادمك | استخدام خادم منشور | الاتصال بخادم بعيد |
|---|---|---|---|
| طريقة الاتصال | يشغّل الوكيل الخادم بأمر داخل بيئتك | ينزّل `uvx` الخادم ويشغّله في بيئتك | يتصل الوكيل بخادم يعمل بالفعل |
| التمرين | STEP 1 وSTEP 2 (خادم المسرد) | STEP 3 (خادم fetch) | STEP 4 (خادم AWS Knowledge) |
| الإعداد | `"command": "uv"` | `"command": "uvx"` | `"url": "https://…"` |

يُستخدم `command` لتشغيل خادم في بيئتك، و`url` للاتصال بخادم يعمل عن بُعد.

## التمرين (30 دقيقة)

خصّص نحو 23 دقيقة للتحضير وتنفيذ الخطوات من STEP 1 إلى STEP 5.

### التحضير — إنشاء الفرع lec06 (نحو دقيقتين)

1. في صفحة نسختك المتفرعة على GitHub، اختر **Sync fork → Update branch** إذا كان هناك تحديث متاح.
2. نفّذ الأوامر التالية بالترتيب في طرفية Codespaces.

```bash
git switch main
git pull --no-rebase
git switch -c lec06
uv sync --frozen
```

3. نفّذ `ls app/mcp_agent.py` وتحقّق من ظهور اسم الملف.

- إذا توقّف `git switch main` بسبب تغييرات متبقية في الفرع السابق، احفظ عملك في commit وأعد المحاولة.
- إذا ظهرت رسالة `a branch named 'lec06' already exists`، انتقل إلى الفرع باستخدام `git switch lec06`.
- إذا ظهر `CONFLICT` عند تشغيل `git pull --no-rebase`، نفّذ `git merge --abort` للحفاظ على تغييراتك، ثم اتبع التعليمات التالية.

#### إذا لم تُكمل عمل محاضرة سابقة

ابدأ من الشيفرة الحالية للمحاضرة 06 في مستودع الدورة. شغّل هذه الأوامر بالترتيب.

```bash
git fetch https://github.com/matsuolab/lecture-ai-engineering-2026-ar.git main
git switch -c lec06 FETCH_HEAD
uv sync --frozen
```

اتبع الطريقة نفسها إذا أظهر Sync fork تعارضًا. احتفظ بعمليات commit بتجنّب خيار **Discard commits**.

### STEP 1 — عرض أدوات خادمك (نحو 4 دقائق)

تحقّق من أن الوكيل يشغّل خادم المسرد ويمرّر أدواته إلى النموذج.

```bash
uv run python -m app.agent --list-tools
uv run python -m app.mcp_agent --list-tools
```

يعمل الأمران دون مفتاح API.

1. يعرض الأمر الأول أدوات الوكيل المستخدم حتى المحاضرة 05، ومنها `search_materials`.
2. يبيّن أول سطر في ناتج الأمر الثاني كيف شغّل الوكيل خادم المسرد. تظهر أدوات الخادم تحته.
3. قارن القائمتين. يتلقى النموذج أسماء الأدوات وأوصافها ووسيطاتها بالصيغة نفسها.

يعرض الأمر الثاني الناتج التالي.

```text
[server] glossary: التشغيل بالأمر (uv run python -m app.mcp_server)
الأدوات التي يراها النموذج: 1

[glossary_search_glossary]
  ابحث في مسرد المقرر وأعِد التعريفات والمحاضرات التي تتناول المصطلحات.

  استخدمها قبل الإجابة عن مصطلحات هندسة الذكاء الاصطناعي أو الكلمات الخاصة بهذا المقرر (AIE2026).
  ضع مصطلحًا واحدًا فقط في query (مثل «LoRA»).
  الوسيطات: {"query": {"title": "Query", "type": "string"}}
```

يتألف اسم أداة MCP من اسم الخادم، ثم شرطة سفلية، ثم اسم الأداة. في `glossary_search_glossary`، يأتي `glossary` من ملف الإعداد، و`search_glossary` هو اسم الدالة في `app/tools.py`. تميّز البادئة الأدوات المتطابقة في الاسم بين الخوادم.

### STEP 2 — سؤال الوكيل وفحص استدعاء الأداة (نحو 4 دقائق)

تحقّق من استدعاء أداة خادم MCP حين يجيب الوكيل عن سؤال.

```bash
uv run python -m app.mcp_agent --trace "ما مستويات الواجب الثلاثة في دورة AIE2026؟"
```

هذا هو سؤال التمرين في المحاضرة 03. افحص الأسطر التالية بعد `--- trace ---`.

1. يعرض `[tool call]` الأداة `glossary_search_glossary` والوسيطات التي اختارها النموذج.
2. يعرض `[tool return]` محتوى المسرد الذي أعاده خادم MCP.
3. يعرض `[usage]` ردّين على الأقل من النموذج. في الرد الأول يستدعي النموذج الأداة، ثم يقرأ النتيجة ويجيب في الرد التالي.

في المحاضرة 03 استدعى الوكيل الدالة مباشرةً. هنا يستدعي خادم MCP الدالة ويعيد نتيجتها إلى الوكيل.

### STEP 3 — تنزيل خادم منشور واستخدامه (نحو 5 دقائق)

أضف fetch، وهو خادم يسترجع صفحات الويب، إلى الإعداد وتحقّق من أن الوكيل يستطيع استخدامه.

1. افتح `app/mcp_servers.json`. ضع فاصلة بعد قوس الإغلاق لـ `glossary`، ثم أضف الأسطر الأربعة الخاصة بـ `"fetch"`.

```json
{
  "mcpServers": {
    "glossary": {
      "command": "uv",
      "args": ["run", "python", "-m", "app.mcp_server"]
    },
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch==2026.11.11", "--no-readability-js"]
    }
  }
}
```

2. شغّل الأمر الأول. تحقّق من ظهور `[server] fetch: التشغيل بالأمر` ومن إضافة `fetch_fetch` إلى القائمة.
3. اطرح السؤال بالأمر الثاني. ابحث عن `fetch_fetch` وعنوان URL في سطر `[tool call]`.

```bash
uv run python -m app.mcp_agent --list-tools
uv run python -m app.mcp_agent --trace "لخّص مقدمة https://modelcontextprotocol.io/ بالعربية في ثلاثة أسطر."
```

- ينزّل `uvx` برنامجًا منشورًا ويشغّله. يعمل خادم fetch داخل Codespace الخاص بك. يستغرق الأمر الأول نحو 10 ثوانٍ عند تشغيله أول مرة.
- يثبّت `==2026.11.11` الإصدار لأن تحديثات الخوادم الخارجية قد تغيّر سلوكها.
- يطلب الخيار `--no-readability-js` استخراج محتوى الصفحة باستخدام Python وحدها.
- يصل وصف `fetch_fetch` إلى النموذج بالإنجليزية كما كتبه منشئ الخادم.

### STEP 4 — الاتصال بخادم يعمل عن بُعد (نحو 5 دقائق)

اتصل عبر URL بخادم MCP الذي تستضيفه AWS، وتحقّق من أن الوكيل يستطيع استخدامه.

1. افتح `app/mcp_servers.json`. ضع فاصلة بعد قوس الإغلاق لـ `fetch`، ثم أضف السطر الخاص بـ `"aws"`.

```json
{
  "mcpServers": {
    "glossary": {
      "command": "uv",
      "args": ["run", "python", "-m", "app.mcp_server"]
    },
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch==2026.11.11", "--no-readability-js"]
    },
    "aws": {"url": "https://knowledge-mcp.global.api.aws"}
  }
}
```

2. شغّل الأمر الأول. ابحث عن `[server] aws: الاتصال بعنوان URL` وعن أدوات تبدأ أسماؤها بـ `aws_`.
3. اطرح السؤال بالأمر الثاني. ابحث عن أداة تبدأ بـ `aws_` في سطر `[tool call]`.

```bash
uv run python -m app.mcp_agent --list-tools
uv run python -m app.mcp_agent --trace "ابحث في وثائق AWS واشرح في سطرين ميزة إدارة الإصدارات في Amazon S3."
```

تبدأ نتيجة الأمر الأول بهذه الأسطر الثلاثة.

```text
[server] glossary: التشغيل بالأمر (uv run python -m app.mcp_server)
[server] fetch: التشغيل بالأمر (uvx mcp-server-fetch==2026.11.11 --no-readability-js)
[server] aws: الاتصال بعنوان URL (https://knowledge-mcp.global.api.aws)
```

الخادم يعمل لدى AWS بالفعل. يتصل الوكيل مباشرةً بعنوانه، ويُرسل السؤال إلى AWS.

### ما الذي تتحقّق منه قبل إضافة أدوات خارجية

في STEP 3 وSTEP 4 استخدمت خوادم من مزوّدين آخرين بإضافة بضعة أسطر للإعداد. تحقّق أولًا مما يلي.

1. **من يوفّر الخادم؟** اعرف المزوّد وأين تُنشر الشيفرة المصدرية. يوفّر مستودع MCP خادم fetch، وتوفّر AWS خادم AWS Knowledge. أضف الخوادم التي يمكنك التحقّق من مصدرها.
2. **ما المخاطر الموثّقة؟** اقرأ التنبيهات والإعدادات الافتراضية في README أو الصفحة الرسمية. يصف README لخادم fetch خطر الوصول إلى عناوين IP داخلية. وعند استخدام خادم بعيد، تُرسل المدخلات التي تمرّرها إلى الأداة إلى مزوّد الخادم.

تحمي إعدادات fetch الافتراضية الموارد الداخلية وتحترم قواعد المواقع بشأن الاسترجاع الآلي.

| السلوك الافتراضي | الخيار |
|---|---|
| يتخطّى العناوين الخاصة مثل `localhost` والشبكات الداخلية | يتيح `--allow-private-ips` الوصول إليها |
| يتخطّى الصفحات التي يمنع موقعها الاسترجاع الآلي في `robots.txt` | يتيح `--ignore-robots-txt` الوصول إلى تلك الصفحات |
| يسترجع الصفحات الأخرى من أي مضيف | يحدّد `--allowed-hosts` المضيفين المتاحين |

تحقّق من المزوّد والمخاطر الموثّقة قبل إضافة أي خادم، بما في ذلك الخوادم في مستودع MCP.

### STEP 5 — تسليم العمل وإيقاف Codespaces (نحو 3 دقائق)

سجّل النتائج في `answer.md`، وافتح طلب سحب (PR)، ثم أوقف Codespace.

1. افتح `lectures/06/answer.md`. ألصق اسم الأداة من STEP 1 وأسطر `[tool call]` من STEP 2 إلى STEP 4، بالأسماء والوسيطات كما ظهرت.
2. احفظ التغييرات باستخدام commit وادفعها باستخدام push.

```bash
git add -A
git commit -m "تمرين المحاضرة 06"
git push -u origin lec06
```

3. في GitHub، افتح PR من `lec06` إلى `main` داخل نسختك المتفرعة. تحقّق من أن المستودع الأساسي هو نسختك المتفرعة.
4. اختر **Codespaces** أسفل اليسار، ثم **Stop Current Codespace**.

مثال على ما يمكنك كتابته في `answer.md`.

```text
- اسم الأداة في STEP 1 — glossary_search_glossary
- STEP 2 [tool call] — glossary_search_glossary({'query': 'مستويات الواجب الثلاثة'})
- STEP 3 [tool call] — fetch_fetch({'url': 'https://…'})
- STEP 4 [tool call] — aws_… (ألصق السطر كما ظهر)
```

إذا لم تُكمل STEP 4، سلّم ما أنجزته وادفع بقية العمل لاحقًا إلى الفرع نفسه.

### استكشاف المشكلات وإصلاحها

إذا استمرت المشكلة، أرسل وصفها والرسالة التي ظهرت في المحادثة.

| المشكلة | الإجراء |
|---|---|
| تظهر `No module named app.mcp_agent` | حدّث `main` حسب خطوات التحضير. نفّذ `git switch lec06` ثم `git merge main` |
| تظهر «تعذّرت قراءة app/mcp_servers.json» | تحقّق قرب السطر المذكور من وجود فواصل بين الخوادم وأزل أي فاصلة زائدة بعد الخادم الأخير |

| يفشل الاتصال بعد إضافة `aws` | تحقّق من صحة عنوان URL. قد يكون السبب حدّ الطلبات، فانتظر قرابة دقيقة وأعد المحاولة |
| بلوغ حدّ الطلبات | انتظر قرابة دقيقة وشغّل الأمر مجددًا |
| لم يُعثر على `GEMINI_API_KEY` | سجّل المفتاح بصفته سرًّا في Codespaces وفق خطوات المحاضرة 01، ثم أعد تشغيل Codespaces |

### الواجب التطبيقي

1. أتح `make_quiz` من المحاضرة 03 في `app/mcp_server.py` كما في الواجب الأساسي. لإنشاء أداة جديدة، عرّف دالة في ذلك الملف وضع `@server.tool()` فوقها مباشرةً.
2. استخدم `return` لإعادة رسالة واضحة عند تمرير وسيط خارج النطاق، مثل رقم محاضرة غير موجودة.
3. اطرح سؤالًا يتضمّن وسيطًا خارج النطاق وافحص `--trace`.

```bash
uv run python -m app.mcp_agent --trace "أنشئ اختبارًا قصيرًا للمحاضرة 99."
```

- تظهر رسالة `return` في سطر `[tool return]` وتصل إلى النموذج.
- يظهر الاستثناء الناتج عن `raise` في سطر `[tool error]`. قارن ما يتلقاه النموذج في الحالتين.

| السؤال | ما تبحث عنه |
